# タスク管理アプリ（MVP）要件定義書

## 1. 目的・スコープ
- 目的: 個人が日々のタスクを期限・優先度・ステータス付きで管理できるWebアプリを最短で公開する。
- 対象ユーザー: 個人（1人1アカウント、他ユーザーとのデータ共有なし）
- 開発体制: 1人開発、無料枠（Vercel Hobby / Supabase Free）で運用
- 対応環境: レスポンシブ（PC/スマホのモダンブラウザ）、UIは日本語のみ

## 2. 機能要件（MVP）
### 2.1 認証（Supabase Auth）【公開前に追加】
開発中はログイン機能を表示・実装せず、タスク機能の開発を優先する（開発中は認証なしで直接タスク画面を開く）。ログイン機能は本番公開の前に追加し、追加完了を公開の必須条件（リリースゲート）とする。
- FR-A1 メール+パスワードでの新規登録・ログイン・ログアウト
- FR-A2 未ログイン時はタスク画面へアクセス不可（ログイン画面へリダイレクト）
- FR-A3 パスワード再設定（メール）※Supabase標準機能の範囲で対応
- FR-A4 開発中は固定の開発用ユーザーとして動作する。ログイン追加時にこの仕組みを撤去する

### 2.2 タスク管理
- FR-T1 作成: タイトル(必須)、説明、期限日、優先度、ステータス、ラベル
- FR-T2 一覧表示・編集・削除（削除は確認ダイアログ付き）
- FR-T3 完了/未完了の切替
- FR-T4 優先度: 高/中/低。期限日: 日付（任意）。期限切れは視覚的に強調
- FR-T5 並べ替え: 期限日順・優先度順・作成日順

### 2.3 カンバン
- FR-K1 ステータスは固定3列: 未着手 / 進行中 / 完了
- FR-K2 ドラッグ&ドロップでステータス変更（スマホではタスク編集からも変更可）
- FR-K3 一覧表示とカンバン表示の切替
- 備考: 「完了」ステータスと FR-T3 の完了フラグは同一概念として扱う（status = done）

### 2.4 ラベル・検索
- FR-L1 ラベルの作成・名称変更・削除、色指定
- FR-L2 1タスクに複数ラベルを付与可能
- FR-L3 キーワード検索（タイトル・説明）
- FR-L4 絞り込み: ラベル / ステータス / 優先度

## 3. MVP対象外（将来対応）
リマインダー通知、サブタスク/チェックリスト、ダークモード、チーム共有、多言語、ユーザー定義のカンバン列、ソーシャルログイン

## 4. 非機能要件
- NFR-1 性能: 一覧初期表示 約2秒以内（タスク数〜1,000件想定）
- NFR-2 セキュリティ: SupabaseのRLS（Row Level Security）を全テーブルで有効化し、公開時は `user_id = auth.uid()` の行のみ操作可。環境変数・サービスロールキーはクライアントへ公開しない。開発中の認証なし動作は開発用Supabaseプロジェクトに限定し、本番プロジェクト・本番URLには持ち込まない
- NFR-3 可用性: 無料枠の範囲（SLAなし）。Supabase Freeは無操作で一時停止され得る点を許容
- NFR-4 ブラウザ: Chrome / Safari / Edge / Firefox の最新版
- NFR-5 アクセシビリティ: キーボード操作・十分なコントラストなど基本配慮
- NFR-6 保守性: TypeScript、ESLint/Prettier、環境変数は `.env.local`（Git管理外）

## 5. システム構成
| 領域 | 採用技術 |
|---|---|
| フロント/サーバー | Next.js (App Router) + TypeScript、Node.js LTS |
| DB/認証 | Supabase（PostgreSQL, Auth）、`@supabase/ssr` |
| ソース管理 | GitHub（main + 作業ブランチ） |
| ホスティング/CI | Vercel（GitHub連携。mainへのpushで本番、PRでプレビュー） |
| UI | Tailwind CSS（+ ドラッグ&ドロップに dnd-kit） ※実装時に最終確定 |

## 6. データモデル（案）
- `tasks`: id(uuid), user_id, title, description, due_date, priority(low/medium/high), status(todo/in_progress/done), position(並び順), created_at, updated_at
- `labels`: id, user_id, name, color, created_at（user_id+nameで一意）
- `task_labels`: task_id, label_id（複合主キー）
- 全テーブルにRLSポリシー（select/insert/update/delete を自分の行のみ許可）

## 7. 画面一覧
1. ログイン / 新規登録 / パスワード再設定
2. タスク一覧（検索・絞り込み・並べ替え）
3. カンバンボード
4. タスク作成・編集（モーダル or 専用ページ）
5. ラベル管理

## 8. 受け入れ基準（抜粋）
- （開発中）ログインなしでタスク作成→カンバンで移動→完了→削除 が一通り動作する
- （公開前）新規登録→ログイン→タスク作成→カンバンで移動→完了→削除 が一通り動作する
- （公開前）未ログインでは本番のタスク画面にアクセスできず、開発用の認証バイパスが残っていない
- 別ユーザーのタスクは参照・更新できない（RLSで確認）
- スマホ幅（375px）で全画面が崩れず操作可能
- Vercel本番URLで上記が動作する

## 9. 開発フェーズ（目安）
1. 環境構築（Next.js, Supabase開発用プロジェクト, GitHub, Vercel連携）
2. DB（ログインなしで動かす開発用設定）
3. タスクCRUD + 一覧
4. カンバン
5. ラベル・検索・絞り込み
6. レスポンシブ調整・テスト
7. **ログイン機能の追加**（認証、RLS本番ポリシー適用、開発用バイパス撤去）← 本番公開前の必須ゲート
8. 本番公開

## 10. 未確定事項・リスク
- MVPとしては機能がやや多め（カンバンDnD・ラベル・検索）。工数超過時は「ラベル」「検索」を後回し候補とする
- UIライブラリ（Tailwind/shadcn等）とDnDライブラリは実装着手時に確定
- Supabase無料枠の一時停止対策（必要なら定期アクセス）
- ログインを後付けするため、公開前にRLS切替・既存データのユーザー紐付けが必要（開発データは破棄する前提）。認証なしのまま本番公開しないこと
